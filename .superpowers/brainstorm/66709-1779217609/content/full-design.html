1. Piece Registry ETL — Show All Available Pieces

A build-time script (scripts/build-piece-registry.ts) reads CDT_BuildingData.json (659 pieces), maps each UE asset path to a local GLB under src/, and emits src/data/pieceRegistry.generated.ts containing both MODEL_PATHS and PIECE_CATALOG. Replaces the hand-maintained modelRegistry.ts and pieces.ts. Run with npm run build:registry.

Pieces without a found GLB get a placeholder entry (no 3D model, shown greyed out in catalog). The generated file also captures buildableGroupType, tier, faction, and connectionCost directly from the CDT data, so the designer always reflects the current game state.

Thumbnails rendered off-screen by a single shared Babylon engine → cached as data: URLs → displayed as <img> tags. Lazy via IntersectionObserver — only pieces scrolled into view get rendered. Re-renders when substrate mode toggles. Greyed-out tile with "—" for pieces missing a GLB.

3. Placement Ghost — Real Materials + Rotation

Ghost mesh currently uses flat transparent green. Updated: ghost uses actual substrate materials with an additive semi-transparent overlay (green when valid, red when invalid). The ghost updates on every pointer move and on every rotation.

Scroll wheel rotation: While activeTool === 'place', the wheel event fires instead of camera zoom. Each detent = 90°. Ghost re-renders immediately. R key continues to work. When the tool changes away from 'place', wheel resumes controlling camera zoom.

Note: Substrate materials on the ghost require the ghost to go through the same material load path as real pieces. The ghost will share the preloaded container from PieceManager's cache, so no extra network requests.

4. Foundation Support System

Data source: socket costs from DT_DuneSocketCostsData.json (Foundation_Edge=100, Up/Sideways/Down=10) and foundation health from CDT (Tier0=5000, Tier1=7000, Tier2=10000).

Rules:

  • At least 1 Foundation must exist before any other piece can be placed
  • Every non-foundation piece must be connected (directly or transitively) to a Foundation
  • Each Foundation has a weight budget = its tier health value
  • Pieces touching Foundation edges (walls/pillars/doors) cost 100 each
  • Pieces connecting via Up/Sideways/Down sockets (stacked floors, upper walls) cost 10 each
  • If total cost across all pieces routed through one Foundation exceeds its budget, placement is blocked

New file: src/engine/SupportSystem.ts — validates placement, computes per-foundation load. Ghost turns red + tooltip "No foundation support" or "Foundation at capacity" when invalid. Inspector panel shows weight budget bar per foundation.
